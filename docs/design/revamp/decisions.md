## Other decisions made during the revamp

- **Palette from the primary colour** (phase 5, ADR 0008): every UI colour is generated from the college's primary hue so any choice looks considered and passes contrast. The college's accent colour is kept (same clamping); the secondary colour is used only for its logo. The Branding screen becomes a preview of the generated palette in phase 10.
- **Fonts** (phase 5, ADR 0008): Geist replaces Figtree, Anek Telugu replaces Noto Sans Telugu and Geist Mono replaces IBM Plex Mono, after a side-by-side English and Telugu comparison. Bricolage Grotesque stays for display.
- **Primitives** (phase 7): `Sheet` (bottom on phones with a drag handle and swipe-down to close, a side sheet from the right on wider screens) is separate from `Dialog` (bottom sheet on phones, centred on wider screens); both are history entries, scroll their body and can pin a footer. Sheets have two positions (open and closed), not snap points: every sheet in the app is content-height, and a half-open state would hide actions. Route tabs (`TabNav`) keep the solid brand highlight; in-page view switches (`Segmented`) use a tinted highlight, so "where you are" and "how you view it" read differently; in-page tabs (`Tabs`) use a sliding underline.
- **Browser baseline**: OKLCH colours, `color-mix()` and `linear()` easings need Chrome 111+, Safari 16.4+ and Firefox 128+, the same baseline Tailwind 4 already sets for this app.

## Phase 9 (AI study assistant) decisions

- **Provider calls are raw HTTP through `safeFetch`**, not the providers' SDKs. The repository rule is that every server-side fetch goes through the SSRF-safe fetcher (private ranges, redirects, size and time caps), and a custom endpoint is tenant input. One small adapter file per provider keeps "adding a provider is one file" true and adds no dependencies.
- **No provider is the default.** A new college starts _not configured_ (library, keyword search and passage answers), not on the demo responder; the demo is an explicit choice, labelled as a demo to students.
- **Anthropic default model:** `claude-opus-5-5`. Other providers have no default model: the admin picks from the models "Test connection" reports, so we never guess a model name.
- **Consent gates external providers only.** The demo responder sends nothing, so it needs no data notice; every other provider (answers or embeddings) stays off until the admin accepts the current notice version.
- **Who takes a subject:** a branch × batch rule plus per-student overrides. The platform does not store a student's current semester, so semester is descriptive and the batches a subject lists decide who takes it (an assumption to confirm with colleges).
- **Granting contributors** uses the existing `capabilities:grant` permission (college admins), since it is the same kind of decision as granting the certified-contributor capability.
- **Signed media links** (owner decision Q9, step 2): study files are served through five-minute HMAC links that re-check access on every request, not through long-lived URLs, so taking a member out of a subject or taking material down works at once. The PDF viewer, the media player and downloads all use them; an expired link mid-video is re-signed and playback resumes.
- **Video links behind a facade** (step 2): YouTube and Vimeo players load only when a student presses play, through the privacy-enhanced embeds. Provider thumbnails are not shown (they would be a request to the provider before play), so `img-src` is unchanged and `frame-src` gains exactly the two embed origins.
- **pdf.js has a budget exception** (step 2): the PDF viewer adds about 129 KB gzipped, loaded only when a PDF is opened (its worker is served from our origin). Rendering pages ourselves keeps search, highlights and deep links to a page, which the browser's own viewer cannot do inside the app.
- **Material review** (step 2): faculty and admins publish at once; alumni contributors' and students' uploads (students only when a subject allows it) wait for a subject owner. Nobody's upload skips the rights attestation.
- **Transcription without a key** (step 2): a platform-run Whisper service is preferred; otherwise a college that uses OpenAI (and accepted the notice) can use OpenAI's transcription; otherwise the uploader is asked for captions. Uploaded captions always win over generated ones.
- **Vectors live on the passages** (step 3): MongoDB keeps every vector as float32 bytes with the model that made it, and the vector store is an index over them. Rebuilding or moving the index costs nothing at the provider, and the in-memory store survives restarts. The cost is about 6 KB per passage in MongoDB for a 1,536-dimension model.
- **In-memory vectors by default, Qdrant for production** (step 3): `VECTOR_STORE=auto` uses Qdrant when `QDRANT_URL` is set. The in-memory store is right for development and a single server; with several API servers each would only see its own writes, so the deployment guide asks for Qdrant there.
- **The search box shows only meaningful matches** (step 3): passages found only by meaning need a cosine similarity of at least 0.3 and are labelled "Similar meaning"; the chatbot keeps the nearest passages and decides with the confidence signal instead.
- **Re-ranking is off by default** (step 3): the LLM re-ranker sends candidate passages to the answer model on every question; it is a platform switch (`AI_RERANKER=llm`) until colleges ask for it.
- **Chunks never cross a page** (step 2 fix): a citation must name the page its words are on, so a page change always starts a new passage, even when that makes short passages for slide decks.
- **Streaming through `safeFetch`** (step 4): providers stream their answers (server-sent events), and `safeFetch` hands each body piece over as it arrives while keeping its size cap, DNS pinning and deadline, plus a cancel signal for Stop. The SDKs would have bypassed the SSRF-safe fetcher.
- **Follow-ups without an extra model call** (step 4): a short follow-up borrows the previous question's words for retrieval, and the last three turns go to the model. Rewriting questions with the model would add latency and tokens to every follow-up.
- **"Ask about this" is a source** (step 4): the words a member selects in the viewer are material, so they go in a numbered `<source>` block like any passage and can be cited, never as instructions.
- **Model answers are stored verbatim** (step 4, ADR 0007 addendum): `plainText()` would strip `<int>` from `vector<int>`; answers are only ever rendered as text, so control and bidi characters are removed and nothing else.
- **KaTeX with MathML output** (step 4): the browser draws MathML, so no KaTeX fonts or stylesheet ship; KaTeX loads only when an answer has maths (75 KB, a recorded budget exception).
- **Quiz points** (step 4): finishing a quiz is the "quiz complete" moment ADR 0008 celebrates; it earns 5 points (`study_quiz`, at most 5 a day) once per quiz.
