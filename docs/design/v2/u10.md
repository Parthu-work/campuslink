# U10 · Speed, feedback and polish

Prompt 3, Part U, phase U10. Nothing new to do; everything already there answers sooner, says what happened, and can be taken back. Shipped in three parts: **U10a**, feedback (Undo on what can be taken back, one error pattern, no spinner on a screen's load); **U10b**, speed (the load path for sign-in and Home, fonts, images); **U10c**, polish (skeletons shaped like the screen, list-to-detail transitions).

## Who it is for and the job

Everyone, on a mid-range Android phone over a patchy 4G connection: tap, see the result at once, and be able to take it back; when something fails, read one short line and retry.

## U10a · Feedback

### Two kinds of Undo

- **Sent at once, Undo sends the opposite** (`toast.undo`): save a post or a job, RSVP, follow or stop following a person, mark a roadmap step done. The change is optimistic: it shows at once and goes back if the server says no.
- **Sent after 6 s, Undo cancels** (`sendAfterUndo`, `lib/undoable.ts`): accepting or declining a mentorship request or a micro-ask, because the other person is told and the server cannot take that back. The screen shows the answer at once; if the page is closed or hidden before 6 s, whatever is waiting is sent then (a `keepalive` request), and its toast goes away, so nothing is lost and no Undo is offered that would not work.

```
360 ──────────────────────────────
 Waiting for you
 ┌──────────────────────────────┐
 │ (A) Ananya wants a 1:1 …     │
 │                Accepted ✓    │
 └──────────────────────────────┘
          ┌───────────────────────────┐
          │ You accepted Ananya.  Undo │
          └───────────────────────────┘
```

Topic and source chips (Following, the welcome screen's interests) keep no toast: the chip is its own undo, and a toast per chip would be noise.

### One error pattern

```
┌─────────────────────────────────────────┐
│ ⚠ Couldn't load this.          [Retry]  │
│ ▸ Details                               │
│   Reference: 9f2c1a7e                   │
└─────────────────────────────────────────┘
```

`ErrorState` is that line wherever a read fails (a screen, a card, a list), with "You're offline. This opens when you reconnect." when the device is offline. The large illustrated error screen goes; `compact` only tightens the padding.

### Haptics and sound

`haptic()` stays behind the member's own setting (off by default); no sounds anywhere.

## U10b · Speed

- **One file for the app's first load** (`vite.config.ts`, `codeSplitting` group `app`, tag `$initial`): the same code in 2 files instead of 22, and 7.6 KB smaller gzipped (162.6 → 155.0 KB). Screens' own shared code keeps Rolldown's split.
- **The mesh background** reads the theme's colours once (and on a theme change), not five times a frame; one still frame paints at once, the motion starts after 2.5 s at about 24 frames a second.
- **Images fetched with the session** (`useFileUrl`): avatars always ask for the small copy (160 px, 320 above 56 px), not only with data saver on; avatars and feed photos are fetched only within about a screen of the viewport (`useNearViewport`, one shared observer). The boxes keep their size meanwhile (initials, the photo's aspect box), so nothing moves.
- **The landing's start race** (`boot.js`): under the landing's first paint, the app's files start when the browser reports that paint (`first-contentful-paint`), not on a frame callback that could run before it.
- **Fonts**: unchanged and checked. The Latin UI face (Geist) is preloaded by `boot.js`; the display face loads with the first heading that uses it; Telugu and Devanagari faces download only when such text is on screen (no request in an English run).

Measured with Lighthouse (mobile, simulated throttling) against `vite preview` on this machine: see progress-3 › U10b.

## U10c (next)

Skeletons that match each screen's final layout, the boot mark without a spinner, and list-to-detail transitions through `animateScreens()`.

## States

- Undo toast: 6 s, the action's own words, one Undo button (a real button in the toast region, reachable by keyboard).
- A failed Undo or a failed answer: the screen goes back and an error toast says so.
- Offline: answers wait in the toast window as online; when sent, a network failure rolls back with the offline line.
