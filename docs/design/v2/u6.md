# U6 · Mentors and mentorship

Prompt 3, Part U, phase U6. Built on U1's primitives (`PersonCard`, `ListRow`, `Stepper`, `ChoiceGroup`, `SlotPicker`) and U5's Home. Shipped in two parts: **U6a**, finding a senior and asking (the match, the request sheet, "Seniors on this path"), and **U6b**, after asking (the session page, the mentor's queue, rematch and nudges).

## Who it is for and the job

A student who wants one specific senior's help: see who fits and why in plain words, pick one, and send a request the senior can say yes to in a minute. Then the senior: see what is waiting and answer in one tap.

- **Strength**: "Strong match" (60 and up), "Good match" (30–59), "Possible match" (under 30), then the reasons in short form. The number shows beside "Strong match" only, and never to a minor (`me.minor`). Reasons are the API's (`MatchReason`): nothing is added.
- **Filters** (company, role, branch, language, free in the next two weeks) narrow the ranked list on the device; their options come from the list itself, so none is ever empty. Ranking is unchanged.
- **Request** opens the request sheet in place (desktop pane or phone card); **Not now** moves to the next senior as Pass did; the name (phone) or **Full profile** (desktop) is the mentor page. Arrow keys still work on the phone card, which is compact so both buttons are on the first screen; the phone's intro line shows in the list view only, and the page header's duplicate "Requests" button is gone (it is in the section row).
- **Role line**: `jobTitle at company` (or either alone); the headline only when it is not the same words; the seed's "DEMO" and "(demo)" markers become one "Demo" badge.

## U6a · The request sheet (`features/mentors/request-form.tsx`)

1. **What you need**: the senior's session types, each with a one-line plain description ("A practice interview with feedback on what to improve") and its length; a résumé or practice report to share where it applies (unchanged).
2. **Your goal**: "What are you working towards?" and "What would help most?", each one short field with an example. Together they become the one message the API takes (`message`, 20–1,500 characters), headed "Goal:" and "What I need:", so seniors keep the structure they already get.
3. **When** (bookable types: the senior's free slots) and **What {name} will see**: the session type and time, the two answers as the senior will read them, and what is shared. Send.

Back keeps everything; the sent state and the tracking link are unchanged.

## U6a · Seniors on this path (`features/mentors/seniors-on-path.tsx`)

On a career path, under the journey: up to three seniors whose job title contains the role the path leads to (`/mentors?q=<role>`, then checked against the job title on the device, so the reason is true): "Works as Software Engineer at Nimbus Labs", and **Ask**, which opens that senior's request sheet. Shown to members who can request mentoring; nothing when no one matches.

## U6b · After asking

- **A session's page** (`/sessions/:id`): the same card as Sessions (Join from 10 minutes before, move, cancel, calendar, message, then feedback and the review prompt), **What it's for** (the request's message as the senior received it) and **Shared notes** both participants edit (`PUT /bookings/:id/notes`, participants only; cleared when either account is erased; in the data export). Reached from Sessions ("Open session"), an accepted request ("View session") and Home's Join (with the join dialog open).
- **The mentor's queue** at the top of the mentoring dashboard: requests waiting with **Accept** (one tap) and **Decline** (the four kind replies by name), the week's count against the cap, and Requests for another time or a note.
- **Rematch** (B5) as a calm line with the seniors' faces: "Rahul hasn't replied yet. Here are 3 seniors who usually reply within a day."

## Acceptance

From the Mentors tab, a request is sent in at most 7 taps by the U0.2 rules (was 7: Mentors → card → profile → Request → type → goal → slot → Send; now Mentors → Request → type → Continue → two fields → Continue → slot → Send, with the profile no longer required). Zero axe violations in both themes; en/te/hi at 360 with no overflow; no number for a minor; e2e: filter the list on desktop, request from the card on a phone through the three steps with the preview, and "Seniors on this path" on a path.
